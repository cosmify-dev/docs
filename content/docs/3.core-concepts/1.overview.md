# Core Concepts

This guide introduces the fundamental concepts you need to understand to effectively use Cosmify.

## Architecture Overview

Cosmify follows a client-server architecture with three main layers:

```
┌─────────────────────────────────────────────┐
│          Frontend Dashboard (Vue.js)        │
│              (Port 3000)                    │
└──────────────────┬──────────────────────────┘
                   │ HTTP/REST
┌──────────────────▼──────────────────────────┐
│          Backend API (Express.js)           │
│              (Port 3001)                    │
└──────────────────┬──────────────────────────┘
                   │ TypeORM
┌──────────────────▼──────────────────────────┐
│      PostgreSQL Database (Port 5432)        │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│        Managed Servers (via SSH)            │
│          Running Docker Containers          │
└─────────────────────────────────────────────┘
```

## Key Components

### 1. Organizations

Organizations are the top-level entity in Cosmify's hierarchy. They provide:

- **Multi-tenancy**: Separate different teams or clients
- **Resource isolation**: Each organization has its own projects and resources
- **Access control**: Manage team members and their permissions
- **Billing boundaries**: (Coming soon) Separate billing per organization

**Example Use Cases:**
- One organization per company
- One organization per client (for agencies)
- Separate organizations for development and production

### 2. Projects

Projects group related applications and services together. They provide:

- **Logical grouping**: Keep related containers organized
- **Environment separation**: dev, staging, production projects
- **Resource sharing**: Share networks and volumes within a project
- **Team collaboration**: Assign team members to specific projects

**Best Practices:**
- Create separate projects for different applications
- Use naming conventions: `app-name-environment` (e.g., `website-production`)
- Group microservices of the same application in one project

### 3. Servers

Servers are the physical or virtual machines where your containers run. They:

- **Host containers**: Execute your Docker containers
- **Provide resources**: CPU, memory, and storage
- **Network connectivity**: Enable container communication
- **Remote management**: Managed via SSH from Cosmify

**Server Types:**
- **Cloud VPS**: DigitalOcean, AWS EC2, Linode, etc.
- **Bare metal**: Physical servers in your datacenter
- **Local**: Development machines

**Server Requirements:**
- Linux OS (Ubuntu 20.04+ recommended)
- Docker installed
- SSH access
- Sufficient resources for your workloads

### 4. Containers

Containers are the running instances of your applications. They:

- **Run from Docker images**: Pull from Docker Hub or private registries
- **Isolated execution**: Each container runs independently
- **Configurable resources**: Set CPU and memory limits
- **Port mapping**: Expose services to the network
- **Environment variables**: Runtime configuration

**Container Lifecycle:**
```
Created → Starting → Running → Stopping → Stopped → Removed
```

### 5. Networks

Networks enable communication between containers. They provide:

- **Container isolation**: Separate network namespaces
- **Service discovery**: Containers can communicate by name
- **Security**: Control which containers can communicate
- **Bridge mode**: Default Docker networking

**Network Types:**
- **Bridge**: Default, isolated network
- **Host**: Share host's network stack
- **Overlay**: Multi-host networking (coming soon)

### 6. Volumes

Volumes provide persistent storage for containers. They:

- **Persist data**: Survive container restarts and deletions
- **Share data**: Multiple containers can mount the same volume
- **Backup**: Can be backed up independently
- **Performance**: Better performance than bind mounts

**Common Uses:**
- Database data directories
- Application uploads and media
- Configuration files
- Logs

### 7. Environment Variables

Environment variables configure container behavior. They:

- **Runtime configuration**: Set without rebuilding images
- **Secrets management**: Store API keys and passwords
- **Feature flags**: Enable/disable features
- **Service URLs**: Database connections, API endpoints

**Best Practices:**
- Never commit secrets to version control
- Use descriptive names: `DATABASE_URL`, not `DB`
- Group related variables with prefixes: `REDIS_HOST`, `REDIS_PORT`

### 8. Ports

Ports expose container services to the network. They:

- **Map container to host**: Container:80 → Host:8080
- **Enable access**: Make services accessible
- **Load balancing**: (Coming soon) Distribute traffic

**Port Types:**
- **Container Port**: Port the application listens on inside the container
- **Host Port**: Port exposed on the server
- **Public Port**: Port accessible from the internet

## Resource Hierarchy

Understanding the resource hierarchy helps organize your infrastructure:

```
Organization
├── Projects
│   ├── Containers
│   │   ├── Environment Variables
│   │   ├── Port Mappings
│   │   └── Volumes
│   └── Networks
└── Servers
    ├── Docker Engine
    └── System Resources
```

## Data Flow

Here's how a typical deployment works:

1. **User Action**: User clicks "Deploy Container" in the dashboard
2. **API Request**: Frontend sends request to backend API
3. **Authentication**: Backend verifies user permissions
4. **Database Update**: Container configuration saved to PostgreSQL
5. **SSH Connection**: Backend connects to target server via SSH
6. **Docker Command**: Executes `docker run` with configuration
7. **Status Update**: Container status synced back to database
8. **UI Update**: Dashboard reflects new container state

## Security Model

Cosmify implements security at multiple levels:

- **Authentication**: User login with Better Auth
- **Authorization**: Role-based access control (RBAC)
- **Encryption**: HTTPS for web traffic, SSH for server communication
- **Isolation**: Containers run in isolated namespaces
- **Secrets**: Encrypted storage of sensitive data

## State Management

Cosmify maintains state in PostgreSQL:

- **Configuration**: Container definitions, environment variables
- **Metadata**: Project names, descriptions, timestamps
- **Relationships**: Organization → Project → Container hierarchy
- **User data**: Accounts, permissions, SSH keys

The actual container state lives on the Docker hosts, and Cosmify periodically syncs state.
